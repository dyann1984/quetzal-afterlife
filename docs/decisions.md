# Decisiones técnicas

- 2026-10-30: Procesamiento CSV en navegador para evitar transporte o almacenamiento prematuro de datos. UTF-8 es el único formato aceptado en fase 1; no se adivina codificación.
- 2026-10-30: Papa Parse se usa para gestionar correctamente comillas y delimitadores; Vitest para pruebas unitarias. Sin base de datos ni proveedor de IA en esta fase.
- 2026-10-30: Se incorpora la imagen adjunta original sin rediseño. La marca no se licencia automáticamente bajo MIT.
- 2026-10-30 (Fase 2A): No se usa ninguna librería npm de parseo DBF. Las librerías existentes (dbf, shapefile, dbase) tienen dependencias de Node.js incompatibles con el bundle del navegador, no están mantenidas activamente, o añaden peso innecesario para un formato suficientemente documentado. El parser se implementa directamente en `lib/dbf.ts` usando únicamente APIs nativas (`Uint8Array`, `DataView`, `TextDecoder`).
- 2026-10-30 (Fase 2A): Node.js v22 no soporta `ibm437`, `ibm850` ni `ibm852` via `TextDecoder` (el build de ICU que incluye Node.js omite las codificaciones DOS históricas). Se implementan tablas de mapeo manual para CP437, CP850 y CP852 basadas en las tablas Unicode oficiales (unicode.org/Public/MAPPINGS/VENDORS/MICSFT/PC/). Las codificaciones Windows (cp1250–cp1254) sí están disponibles en Node.js v22 y se usan via `TextDecoder`. Esta limitación también puede afectar a algunas versiones antiguas de navegadores embebidos; se documenta en el módulo y en este registro.
- 2026-10-30 (Fase 2A): Los registros marcados como borrados (byte `0x2A`) se incluyen en el resultado con `deleted: true` en lugar de filtrarse. En arqueología digital, la evidencia borrada es evidencia; omitirla cambiaría el registro histórico sin justificación verificable.
- 2026-10-30 (Fase 2A): Compatibilidad demostrada con dBASE III (0x03) y dBASE IV (0x04) mediante fixtures construidos por código. Los dialectos dBASE 5.0 (0x05), FoxPro 2.x con memo (0xF5) y Visual FoxPro (0x30) están en la lista blanca de bytes de versión por documentación del formato, pero no se dispone de fixtures reales representativos; no se afirma compatibilidad funcional plena para esos dialectos.
